## 文案要求

- 每种语言使用独立目录：`scont/{language}/{page}.md`。
- 一个页面只服务一个明确搜索意图，近义词放在同一页，避免重复页面互相竞争。
- Title 和 H1 必须自然包含主关键词；Title 可增加真实卖点，不能只堆关键词。
- 不浪费 H1、H2、H3：每个标题都必须服务主关键词、近义词、格式词、操作词或相关长尾意图。
- H1 聚焦主关键词；H2 覆盖核心子意图；H3 细化步骤、格式、功能或问题词。
- FAQ 区块的 H2 固定使用简短的 `FAQs`，不要重复主关键词或写成长句；具体问题使用 H3。
- 正文紧跟对应标题强化其关键词语义，不添加与页面搜索意图无关的段落。
- 主关键词重复过多时使用目标语言中的自然近义词或变体，避免机械堆词。
- 写正文前搜索 `docs/keyword-data/`，提取同一意图的格式词、操作词、近义词和长尾词。
- 自然相关词可分配到 Title、H2、H3、正文和 FAQ；错拼、混合语言或不自然词形不强行写入。
- 先确定关键词归属页面；已经规划独立页面的格式词、转换词和目标大小词，不在通用页的 Title、H1、H2、H3 中重点优化。
- 通用页可以在正文中自然提及相关专页关键词一次；专页发布后将该处改为描述性内链，不让两个页面争夺同一主关键词。
- 每份文案末尾保留“关键词来源映射”，记录实际使用和明确排除的词。
- 对应功能未实现的关键词只能记录为待做，不能写成当前支持。
- 文档中的 `SEO`、`Hero`、`JSON-LD`、`内链`、`来源映射` 只是编辑标记，不得作为页面 H1、H2、H3 输出。
- 文案必须完整使用目标语言，包括按钮、步骤、FAQ 和结构化数据文本。
- 只描述 [产品功能快照](../product-capabilities.md) 中已实现的功能。
- 转换、拉伸等专用页面应记录需要传给编辑器的白名单预设参数。
- Footer 内链必须遵循 [SEO 页面内链规划](../internal-linking-plan.md)，相关工具总数最多 5 个。
- 页面中段必须按搜索意图选择结构，不得让所有页面重复同一模块顺序。
- 只共用 Header、上传 Hero、FAQ、CTA 和 Footer；六类页面中段分别维护结构与样式，不抽成统一模块。
- 中段模块之间仅使用留白，不添加横贯内容区的分割线或整段背景色；表格、参数面板和功能图形内部可使用必要边框。

## 页面结构类型

| `kind` | 适用意图 | 必须突出 |
|---|---|---|
| `converter` | 格式转换 | 输入输出格式、转换模式、格式差异 |
| `checker` | 图片信息检查 | 文件大小、像素尺寸、格式、结果读数 |
| `resize` | 拉伸与尺寸调整 | 宽度、高度、比例、拉伸与裁剪区别 |
| `general-compressor` | 通用图片压缩 | 输出格式选择、压缩预览、批量处理 |
| `jpg-compressor` | JPG 压缩 | 质量、压缩痕迹、像素尺寸 |
| `png-compressor` | PNG 压缩 | 色板、抖动、透明度 |

上传区、FAQ、CTA 和 Footer 可以共用；中间内容结构不得共用一套固定顺序。

## SEO 字段

每份文案必须包含：

- URL、Language、Title、Meta description、Canonical、H1。
- Robots、Open Graph title、Open Graph description。
- Title 最多 60 个字符，Meta description 最多约 160 个字符；按实际字符数计算，不按字节数计算。
- 页面正文、操作按钮、最终 CTA、内链建议。
- `WebPage`、`WebApplication` 和 `FAQPage` JSON-LD 字段说明。
- 只有存在内容等价且互相引用的语言版本时才输出 hreflang；没有等价版本时不输出。

发布页面时还必须同步检查 title、description、canonical、robots、Open Graph、JSON-LD、内部链接、sitemap、`robots.txt` 和 `llms.txt`。

## FAQ 要求

- 页面 FAQ 区块标题只使用 `FAQs`。
- 每页至少 6 个 FAQ。
- 写 FAQ 前先搜索 [seo-ques.js](../keyword-data/seo-ques.js)，优先选择与当前页面意图相关的问题。
- 将问题自然翻译为页面语言，并在文案末尾保留“FAQ 来源映射”，方便复核。
- `seo-ques.js` 没有足够相关问题时，才根据主关键词、产品功能和用户操作补充问题。
- 不使用无关的品牌、软件、医疗或开发问题凑数量。
- 产品尚未实现的能力可以解释限制，但不能回答成已经支持。
